# Order Book Matching Engine

This project implements a lightweight limit-order book and matching engine in C++17. It supports order submission, best-price matching, FIFO priority within a price level, cancellation, and replay of synthetic market data through the simulation binary.

The current implementation is optimized for a bounded-price domain and high-throughput replay. The key design change from the original map-based version is that price levels are stored in a dense, fixed-range array with a bitmap to track which prices are active.

- Orders are stored in a pre-allocated free-list pool.
- Bid and ask sides each use a `priceLevelArray` over a bounded price range.
- Each active price level keeps a head/tail linked list of orders for FIFO matching.
- Matching is done in the book itself, with trade records retained for inspection and testing.

## Setup and build

From the project root:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build --target simulation order_book_tests order_pool_tests price_level_array_tests
```

This produces:

- `build/simulation` or `build/simulation.exe`
- `build/order_book_tests` or `build/order_book_tests.exe`
- `build/order_pool_tests` or `build/order_pool_tests.exe`
- `build/price_level_array_tests` or `build/price_level_array_tests.exe`

You can also build tests with CTest:

```bash
ctest --test-dir build --output-on-failure
```

The repo still includes a simple `Makefile`, but the CMake flow is the canonical build path.

## Generate synthetic market data

This repo includes a generator that writes CSV-based order flow for replay simulation:

```bash
python scripts/generate-market-data.py 1000 data/market_data.csv 42
```

Arguments:

- `num_ticks`: number of simulated ticks to generate
- `output.csv`: destination CSV file
- `seed`: optional RNG seed, defaults to `42`

Generated rows look like:

```csv
op,id,side,type,price,qty,tick,sequence
NEW,1,BUY,LIMIT,995,12,0,0
CANCEL,2,,,,,,1
```

This is designed to exercise:

- normal limit order flow
- market orders
- random cancellations
- bursty market activity and clustered ticks

## Run the simulation

The simulator reads a CSV of operations and replays them through the order book in one of two modes.

### 1) Invariant mode

Validates book consistency after every operation and catches issues like crossed books or overfilled orders.

```bash
./build/simulation invariant data/market_data.csv
```

On Windows:

```powershell
./build/simulation.exe invariant .\data\market_data.csv
```

### 2) Performance mode

Disables the expensive checking/logging path so the replay can run as quickly as possible.

```bash
./build/simulation perf data/market_data.csv
```

On Windows:

```powershell
./build/simulation.exe perf .\data\market_data.csv
```

The simulator reports total operations processed and throughput.

> Important: the project has a global logging toggle, `SHOULD_LOG`, in `order-book.cpp`. When it is `false`, trade/event arrays are not populated. Correctness tests inspect `book.trades()`, so they expect logging to remain enabled during validation runs.

## Core data structures

### `Order`

Defined in `order.h`.

```cpp
struct Order {
  OrderId id;
  Side side;
  Price price;
  Qty remaining_qty;
  Type type;
  std::uint64_t sequence;
  std::uint32_t next;
  std::uint32_t prev;
};
```

This is the fundamental unit of market activity. It includes:

- `id`: unique order identifier
- `side`: `Buy` or `Sell`
- `price`: limit price for resting orders, ignored for market orders
- `remaining_qty`: quantity still to be matched
- `type`: `Limit` or `Market`
- `sequence`: arrival sequencing metadata
- `prev` / `next`: linked-list pointers used inside the price level and pool

### `PriceLevel`

Defined in `price-level-array.h`.

```cpp
struct PriceLevel {
  Price price;
  Qty total_qty = 0;
  PoolIndex head = kInvalidIndex;
  PoolIndex tail = kInvalidIndex;
  std::uint32_t order_count = 0;
};
```

Each price bucket stores:

- the price itself
- aggregate quantity at that level
- head/tail indexes for the FIFO linked list of resting orders
- the number of active orders at that price

This is the node payload used by the book’s level-array representation.

### `priceLevelArray`

Defined in `price-level-array.h`.

```cpp
class priceLevelArray {
private:
  Price min_price;
  Price max_price;
  Price tick_size;
  size_t num_levels;
  std::vector<PriceLevel> priceLevels;
  std::vector<uint64_t> bitmap;
  size_t active_count;
  size_t lowest_active_index;
  size_t highest_active_index;
};
```

This is the main architectural change in the current codebase. Instead of a `std::map` of active prices, the book keeps a dense array across a bounded price domain.

Key behaviors:

- prices are indexed by `price_to_index()` based on `min_price`, `max_price`, and `tick_size`
- an active bitset tracks which levels currently have resting orders
- `best_bid()` and `best_ask()` are derived from the highest/lowest active index
- updates call `on_level_updated()` to maintain the bitmap and active-index metadata

This makes the book efficient for fixed-range price lattices while still preserving a simple price-time priority model.

### `OrderBook`

Defined in `order-book.h`.

```cpp
class OrderBook {
private:
  Price min_price;
  Price max_price;
  Price tick_size;
  priceLevelArray bids;
  priceLevelArray asks;
  std::unordered_map<OrderId, PoolIndex> order_map;
  OrderPool pool;
  std::vector<Trade> last_trades;
  std::vector<std::string> events;
};
```

Key state:

- `bids`: price-level array for buy orders
- `asks`: price-level array for sell orders
- `order_map`: maps `OrderId` to a pool index for live orders
- `pool`: underlying order storage pool
- `last_trades`: recorded trades from matching
- `events`: optional event log for debugging and validation

The matching logic is implemented in `submit_order()`, which performs:

1. matching against the opposite side
2. reducing `remaining_qty` for aggressor and resting orders
3. removing fully consumed resting orders
4. adding residual limit orders back to the book if they still have remaining quantity

### `OrderPool`

Defined in `order-pool.h`.

This is a custom pre-allocated free-list pool. It stores `Order` objects in a contiguous `std::vector<Order>` and reuses slots via a singly-linked free list.

Core ideas:

- `orders` holds the actual storage
- `free_head` points to the next available index
- `grow()` doubles the pool when full
- `acquire_and_place()` returns a free slot and writes the order
- `release()` returns a slot to the free list

This pattern reduces allocation overhead and keeps order lifecycle handling fast for high-volume simulation workloads.

## Matching behavior

The engine uses price-time priority:

- the current best bid is the highest-priority active bid level
- the current best ask is the lowest-priority active ask level
- crossing checks decide whether the incoming order should match
- within the same price level, older orders are matched first (FIFO)
- fully consumed resting orders are removed from the book
- partially consumed orders remain and keep the same level with reduced `remaining_qty`

For limit orders:

- buy crosses when `incoming_price >= best_ask`
- sell crosses when `incoming_price <= best_bid`

For market orders, the order executes against the opposite book as far as available liquidity allows; any unfilled remainder is left as an unfilled market order state and reported through the logging path.

## File-by-file summary

### `CMakeLists.txt`
Configures the project with C++17, fetches GoogleTest, defines the `order_book_core` library, builds the simulation executable, and sets up the test binaries.

### `Makefile`
Legacy/simple build wrapper. CMake is the primary workflow for this project.

### `order.h`
Defines shared aliases and enums:

- `OrderId`
- `Price`
- `Qty`
- `PoolIndex`
- `Side` (`Buy`, `Sell`)
- `Type` (`Limit`, `Market`)
- `Order`

### `order-pool.h`
Implements the custom free-list memory pool used to store orders.

### `price-level-array.h`
Contains the bounded price-level representation and bitmap-based active-level tracking.

### `order-book.h`
Declares the public interface for the order book, including:

- `Trade`
- `OrderBook`
- order submission/cancel APIs
- accessors for top-of-book, level quantity, and trade log

### `order-book.cpp`
Contains the book logic:

- `push_back()` / `unlink()` for linked-list maintenance
- `add_order()` / `remove_order()` for insertion/removal
- `match_buy()` / `match_sell()` for trade matching
- `submit_order()` / `cancel_order()` for public entry points
- accessors for book state, pricing, counts, and logs

### `matching-engine.h`
Thin wrapper around the `OrderBook` with a higher-level `matching_engine` interface.

### `matching-engine.cpp`
Minimal forwarding implementation that passes through the matching operations.

### `simulation.cpp`
Command-line replay engine for reading market-data CSV files and operating in `invariant` and `perf` modes.

### `scripts/generate-market-data.py`
Creates synthetic market data with bursty volume and cancellations.

### `tests/order-book-tests.cpp`
Exercises matching rules, partial fills, price-time priority, and cancellation logic.

### `tests/order-pool-tests.cpp`
Verifies free-list construction, growth, reuse, and slot recycling behavior.

### `tests/price-level-array-tests.cpp`
Covers interval indexing, active-level tracking, best bid/ask selection, and price-level update semantics.

### `lazycsv.hpp`
High-performance CSV parser used by the simulation layer for large replay datasets.

### `data/market_data.csv` and `data/market_data_large.csv`
Benchmark and replay datasets for validation and performance analysis.

## Notes

- The project is intentionally optimized for replay and benchmark-style simulation rather than a full trading platform API.
- The current implementation uses a bounded price grid and active-price bitmap to favor predictable memory layout and fast price lookup.
- If you extend the engine, the natural places to add functionality are the `OrderBook` matching logic, the `priceLevelArray` bookkeeping, and the simulator input/output layer.
