# Order Book Matching Engine

This project implements a lightweight limit-order book and matching engine in C++17. It supports order submission, matching against the best available price, FIFO priority within a price level, cancellation, and replay of synthetic market data through a simulation binary.

The design is intentionally simple and performance-oriented:

- Orders are stored in a pre-allocated memory pool for low-overhead allocation.
- Price levels are organized in `std::map` for sorted price priority.
- Each price level keeps a doubly-linked list of orders for FIFO processing.
- Matching is performed at the book level, with trade records retained for inspection/testing.

## Prerequisites

- CMake 3.14+

## Setup and build

From the project root:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build --target simulation order_book_tests order_pool_tests
```

This produces:

- `build/simulation` or `build/simulation.exe`
- `build/order_book_tests` or `build/order_book_tests.exe`
- `build/order_pool_tests` or `build/order_pool_tests.exe`

You can also build tests with CTest:

```bash
ctest --test-dir build --output-on-failure
```

If you prefer the repo’s simple Makefile, it is still present, but the CMake flow is the canonical build for this project.

## Generate synthetic market data

This repo includes a generator that creates CSV-based order flow for replay simulation:

```bash
python scripts/generate-market-data.py 1000 data/market_data.csv 42
```

Arguments:

- `num_ticks`: number of simulated ticks to generate
- `output.csv`: CSV path to write
- `seed`: optional RNG seed, defaults to `42`

The generated CSV format is:

```csv
op,id,side,type,price,qty,tick,sequence
NEW,1,BUY,LIMIT,995,12,0,0
CANCEL,2,,,,,,1
```

This is designed to exercise:

- normal limit orders
- market orders
- random cancellations
- bursty market activity with clustered ticks

## Run the simulation

The simulator reads a CSV of operations and replays them through the order book in one of two modes.

### 1) Invariant mode

This mode validates book consistency after every operation and catches violations such as crossed books or overfilled orders.

```bash
./build/simulation invariant data/market_data.csv
```

On Windows:

```powershell
./build/simulation.exe invariant .\data\market_data.csv
```

### 2) Performance mode

This mode strips out invariant checking and disables the expensive bookkeeping/logging path so it can replay the sequence as quickly as possible.

```bash
./build/simulation perf data/market_data.csv
```

On Windows:

```powershell
./build/simulation.exe perf .\data\market_data.csv
```

The simulator will report total operations processed and throughput.

> Important: the project has a global logging toggle, `SHOULD_LOG`, in `order-book.cpp`. When `SHOULD_LOG` is `false`, trade/event arrays are not populated. The unit tests in `tests/order-book-tests.cpp` check the trade log (`book.trades()`) and therefore expect the logging path to be enabled during correctness testing. In other words, the performance mode is intentionally optimized for throughput and not for test assertions.

## Core order book data structures

### `Order`

Defined in `order.h`.

```cpp
struct Order {
  OrderId id;
  Side side;
  Price price;
  Qty remaining_qty;
  Type type;
  std::uint64_t sequence;
  std::uint32_t next;
  std::uint32_t prev;
};
```

This is the fundamental unit of market activity. It carries:

- `id`: unique order identifier
- `side`: `Buy` or `Sell`
- `price`: limit price for a limit order; ignored for market orders
- `remaining_qty`: quantity left to be matched
- `type`: `Limit` or `Market`
- `sequence`: arrival order / sequencing metadata
- `prev` / `next`: linked-list pointers used inside the price level and pool

### `PriceLevel`

Defined in `order-book.h`.

```cpp
struct PriceLevel {
  Price price;
  Qty total_qty = 0;
  PoolIndex head = kInvalidIndex;
  PoolIndex tail = kInvalidIndex;
  std::uint32_t order_count = 0;
};
```

Each limit price is represented as a level containing:

- the price itself
- aggregate quantity at that level
- head and tail of a linked list of orders at that price
- number of resting orders at that price

This makes matching and FIFO behavior efficient while still allowing easy aggregate queries.

### `OrderBook`

Defined in `order-book.h`.

```cpp
class OrderBook {
private:
  std::map<Price, PriceLevel, std::greater<Price>> bids;
  std::map<Price, PriceLevel> asks;
  std::unordered_map<OrderId, PoolIndex> order_map;
  OrderPool pool;
  std::vector<Trade> last_trades;
  std::vector<std::string> events;
}
```

Key internal state:

- `bids`: best bid first, keyed by price
- `asks`: best ask first, keyed by price
- `order_map`: maps `OrderId` to the pool slot holding the live order
- `pool`: the memory pool storing the actual order objects
- `last_trades`: log of trades produced during matching
- `events`: optional event log for debugging/inspection

The trade and event logging is gated by the `SHOULD_LOG` flag in `order-book.cpp`. This is intentionally set to `false` in performance runs to reduce overhead; it is left enabled for correctness checks and tests that inspect the trade log.

The matching logic is implemented in `OrderBook::submit_order()`, and it performs:

1. matching against the opposite side
2. reducing `remaining_qty` for aggressor and resting orders
3. removing fully consumed resting orders
4. adding residual limit orders back to the book if they are still active

### `OrderPool`

Defined in `order-pool.h`.

This is a pre-allocated fixed-capacity pool that uses a free list to recycle slots without expensive dynamic allocation. It is a light custom allocator optimized for high-throughput order processing.

Core ideas:

- `std::vector<Order> orders` holds the actual storage
- `free_head` points to the next available index
- `grow()` doubles capacity when needed
- `acquire_and_place()` returns a free slot and writes the order
- `release()` pushes a slot back onto the free list

This allows the book to process a very large number of new and cancel operations while reusing slots efficiently.

## Matching behavior

The matching engine is price-time priority based:

- best bid and best ask are selected from the top of each side's price map
- crossing checks determine whether an incoming order can trade
- within a price level, older orders are matched first (FIFO)
- fully filled resting orders are removed from the book
- partially filled resting orders remain at the same price level with reduced quantity

For limit orders, crossing is allowed only when the incoming price crosses the best opposing price:

- Buy crosses when `incoming_price >= best_ask`
- Sell crosses when `incoming_price <= best_bid`

For market orders, the order crosses as much as possible and does not rest unless the order cannot be fully filled and the implementation decides to retain a residual (in this codebase, market orders are generally treated as immediate execution only).

## File-by-file summary

### `CMakeLists.txt`
Configures the project with C++17, fetches GoogleTest, defines the `order_book_core` library, builds the simulation executable, and sets up unit test executables.

### `Makefile`
Legacy/simple build entry point. Not the main build path for this repo; CMake is the primary workflow.

### `order.h`
Defines shared aliases and enums:

- `OrderId`
- `Price`
- `Qty`
- `PoolIndex`
- `Side` (`Buy`, `Sell`)
- `Type` (`Limit`, `Market`)
- `Order`

### `order-pool.h`
Implements the custom memory pool used to store orders. Handles allocation, growth, and free-list reuse for low-overhead order lifecycle management.

### `order-book.h`
Declares the public interface for the order book. It includes:

- `Trade` structure
- `PriceLevel` structure
- `OrderBook` class
- order submission/cancel APIs
- accessors for top-of-book, level quantity, and trade log

### `order-book.cpp`
Contains the actual order book logic:

- `push_back()` and `unlink()` for linked-list maintenance
- `add_order()` and `remove_order()` for book insertion/removal
- `match_buy()` / `match_sell()` for trade matching
- `submit_order()` and `cancel_order()` for public entry points
- accessors for book state, pricing, counts, and logs

### `matching-engine.h`
Thin wrapper around `OrderBook` exposing a higher-level `matching_engine` interface.

### `matching-engine.cpp`
Minimal implementation of the matching engine wrapper; forwards order submission and cancellation to the underlying order book.

### `simulation.cpp`
Command-line replay engine for reading market data CSV files and operating in two modes:

- `invariant`: validation mode
- `perf`: performance replay mode

This is used for large-scale market replay benchmarks and correctness checking.

### `scripts/generate-market-data.py`
Synthetic market-data generator. Produces CSV feeds with realistic bursty market activity, directional bias, and scheduled cancellations.

### `tests/order-book-tests.cpp`
Contains GTest coverage for matching rules, trade execution, partial fills, price-time priority, and cancellation behavior.

### `tests/order-pool-tests.cpp`
Covers the custom memory pool’s construction, growth, reuse, and free-list behavior.

### `lazycsv.hpp`
High-performance CSV parser used by the simulator to avoid allocations while reading large market-data files.

### `data/market_data.csv` and `data/market_data_large.csv`
Sample order-flow datasets used for benchmarking and replay.

## Notes

- The project is intentionally optimized for replay and benchmark-style simulation rather than a full trading platform API.
- The order book supports a compact, efficient representation that is suitable for research, simulation, and validation of matching logic.
- If you need to extend the engine, the natural places to add functionality are the `OrderBook` matching logic and the simulator input/output layer.
